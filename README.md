# CloneCraft Studio — مختبر إعادة بناء المواقع

**نسخة تأسيسية 0.1** — أداة محلية بواجهة عربية: أدخل رابط موقع عام، وتُنتج خريطة صفحات ولقطات شاشة ووصفًا لعناصر الواجهة وملف توجيه لوكيل Claude Code أو Codex كي يبدأ **إعادة بناء مستقلة**.

> الهدف ليس استخراج الشيفرة الأصلية أو سرقة هوية الموقع. لا تستطيع الأداة كشف قواعد البيانات أو واجهات الخادم غير المنشورة أو أسرار الأنظمة. لا يوجد في هذه النسخة مولّد كود تلقائي نهائي أو ضمان مطابقة بصرية 100%. إنها مرحلة **الفحص والتوثيق والتخطيط** التي تسبق البرمجة.

## المتطلبات

- Node.js 22.19 أو أحدث وnpm.
- Chromium الذي يثبّته Playwright.
- الجهاز الذي تشغّل عليه الأداة يجب أن يتمكن من الوصول إلى المواقع المصرّح لك بفحصها.

## تشغيل الواجهة العربية

```bash
npm install
npx playwright install chromium
npm run dev
```

افتح **http://127.0.0.1:4317**، أدخل الرابط، وحدد عدد الصفحات (1–15). الأداة لا تستعمل حسابًا مسجّلًا أو جلسات متصفحك. تعمل الواجهة محليًا وتقبل الطلبات من جهازك فقط.

### خيار CLI

```bash
npm run analyze -- --url https://example.com --pages 4 --out reports/example
```

النتائج في `reports/example/`:

- `report.json`: عناوين ومسارات وروابط وحقول وأزرار وتنسيقات ظاهرة.
- `01-home.png` وغيرها: لقطات مرجعية بمتصفح 1365×800.
- `BLUEPRINT.md`: خطة إنشاء موقع مستقل وتوصيات لاختبار التطابق.

## ربط REA مع Claude Code (اختياري)

المشروع لا ينسخ كود REA داخل المستودع؛ يُثبت من **المصدر الرسمي** بعد مراجعة التغييرات:

```bash
npx rea-agents setup
```

اختر Claude Code، راجع الملفات والإعدادات المقترحة، وافق ثم أعد تشغيل Claude Code. المشروع الرسمي: https://github.com/morluto/rea . لا تُشغّل REA على ملفات أو تطبيقات لا تملك تفويضًا بتحليلها.

## من رابط إلى تطبيق

1. **استكشاف** الصفحات الظاهرة والتصميم والعناصر التفاعلية والصور المرجعية.
2. **تحديد المتطلبات** غير المرئية: صلاحيات الدخول، النماذج، قواعد العمل، المخطط البنيوي للبيانات.
3. **إعادة البناء المستقل** بواجهة حديثة وخادم وبيانات **جديدة** من خلال وكيل البرمجة باستخدام `agents/CLAUDE.md`.
4. **التحقق** باختبارات للصفحات، الروابط، الواجهات، وإمكانية الوصول. مقارنة اللقطات تتم الآن يدويًا؛ أتمتتها مرحلة مستقبلية.
5. **النشر** بعد مراجعة الملكية والحقوق والأمان.

## ماذا يمكن استعادته وما لا يمكن؟

| العنصر | الحالة في هذه النسخة |
|---|---|
| الصفحات العامة والروابط والعناوين | استخراج تلقائي محدود |
| الألوان والخطوط وأماكن بعض العناصر | استخراج وصفي أولي |
| لقطات مرئية لشاشات سطح المكتب | نعم |
| تفاصيل كل حركة وتفاعل | لا؛ يتطلب تسجيل التفاعلات وتصريحًا واضحًا |
| رمز المصدر الخلفي وبيانات المستخدمين | غير متاح عبر الفحص العام |
| إنشاء واجهة وخلفية وقاعدة بيانات بالذكاء الاصطناعي | خطة وتوجيه للوكيل؛ ليس تنفيذًا آليًا في 0.1 |
| استنساخ علامة أو محتوى محمي دون ترخيص | ليس هدفًا مدعومًا |

## حدود الأمان

- يستخدم HTTP/HTTPS فقط، ويقيّد المضيف إلى عنوان عام مع حظر نطاقات محلية معروفة، ويرفض POST وأنواع الطلبات غير الآمنة في سياق الفحص.
- هذه إجراءات أولية **ليست عزلًا مضمونًا** ضد DNS rebinding أو ثغرات المتصفح؛ استخدم أداة الفحص فقط على جهاز موثوق، لا تنشر خادمها للعامة ولا تشغّلها بصلاحيات عالية.
- يحتفظ الموقع باللقطات داخل مجلد `reports/` المحلي، والمستبعد من Git.
- يجب الالتزام بشروط المواقع وسياسات الزحف و`robots.txt` وتحديد إذن الاستخدام. **النسخة الحالية لا تطبق robots.txt آليًا**، لذلك لا تعتبرها زاحفًا متوافقًا مع كل المواقع.
- المواقع التي تتطلب دخولًا أو تمنع الوصول الآلي ليست ضمن نطاق هذه النسخة.

## لماذا FilmCraft؟

[FilmCraft](https://github.com/storytold/filmcraft) ليس أداة نسخ مواقع. لكنه يقدم مثالًا معماريًا مهمًا على إعادة تنفيذ **clean-room** لبرنامج معقد، مع طبقة أوامر ومنافذ CLI وMCP للتحكم بواسطة الوكلاء. نحن نستفيد من الفكرة الهندسية؛ **لا ننقل شيفرته إلى هنا**، وهو مشروع تحرير فيديو مستقل تمامًا.

راجع `docs/ARCHITECTURE.md` و`agents/CLAUDE.md` و`docs/AUTHORIZED_USE.md`.
